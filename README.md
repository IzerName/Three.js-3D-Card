# Three.js 3D Card для Home Assistant

**Одна карточка — много 3D-сцен.** Карточка `custom:threejs-3d-card` показывает
интерактивную 3D-модель на three.js, данные берёт из Home Assistant в реальном
времени, а **модель сама объявляет свои переменные** — редактор карточки
автоматически строит из них форму, где вы выбираете устройства и параметры
через штатный выбор сущностей Home Assistant.

```
┌───────────────────────────┐        ┌──────────────────────────────────────┐
│  custom:threejs-3d-card   │        │  модель (JS-файл)                    │
│  ─────────────────────    │        │  ──────────────────────────────────  │
│  • рендерер, камера       │◄───────│  manifest  — паспорт и камера        │
│  • состояния из hass      │        │  bindings  — какие устройства нужны  │
│  • модалка сущности       │───────►│  params    — настройки внешнего вида │
│  • форма-редактор         │        │  create()  — построение сцены        │
└───────────────────────────┘        └──────────────────────────────────────┘
```

* three.js **входит в поставку** — работает в закрытом контуре без интернета
  (CDN можно включить опционально);
* установка и обновления через **HACS**, публичные релизы и CI — репозиторий:
  <https://github.com/IzerName/Three.js-3D-Card>;
* HACS ставит **один файл** — `threejs-3d-card.js` в корне репозитория: three.js,
  загрузчики форматов, ядро и встроенные модели внутри;
* **свой JS-файл модели** можно импортировать прямо в редакторе карточки —
  без пересборки карточки и без публикации репозитория;
* API модели документирован: [docs/MODEL_API.md](docs/MODEL_API.md).

## Что умеет

| Возможность | Как это выглядит |
|---|---|
| **Модели как плагины** | Бак с водой, производственный цех — или ваш собственный JS-файл. Список моделей — в редакторе карточки. |
| **Выбор устройств из списка** | Поля привязок — штатный `ha-entity-picker` с фильтром по домену, `device_class` и единице измерения. Никакого ввода `entity_id` вручную. |
| **Переменные модели → форма** | Модель объявляет `bindings` и `params`; редактор рисует по ним форму. Новая сцена — без правки карточки. |
| **Живая проверка** | Редактор сразу показывает текущее значение выбранной сущности, предупреждает о `unavailable`, отсутствии сущности или неверном домене. |
| **Модалка сущности** | Клик по объекту в сцене — окно с состоянием, атрибутами, временем изменения и кнопками управления, плюс переход в Home Assistant. |
| **Управление** | `switch`, `light` (яркость), `climate` (режим, температура), `cover`, `lock`, `button`, `script`, `automation` — вызовы штатных сервисов HA. |
| **Работа офлайн** | three.js поставляется вместе с карточкой: в однофайловой сборке — внутри `threejs-3d-card.js`, в раскладке `dist/` — рядом (`vendor/three.module.js`). |
| **Бережёт ресурсы** | Один WebGL-контекст на карточку, пауза рендера вне экрана, освобождение ресурсов при удалении карточки, восстановление после потери контекста. |
| **Диагностика** | Панель прямо в карточке: какие привязки заполнены, какие сущности не найдены, что сообщила модель. |

## Установка

### Вариант 1 — HACS (рекомендуется)

1. HACS → **Frontend** → меню (⋮) → **Custom repositories**.
2. Добавьте `https://github.com/IzerName/Three.js-3D-Card`, категория —
   **Dashboard**.
3. Найдите «Three.js 3D Card» в HACS → **Download**.
4. HACS положит в `config/www/community/Three.js-3D-Card/` (имя каталога — имя
   репозитория как есть, с регистром) **один файл** `threejs-3d-card.js` —
   однофайловую сборку, внутри которой three.js r160, загрузчики OBJ/MTL/glTF,
   ядро карточки и встроенные модели. Больше на сервере ничего не нужно: ни
   `src/`, ни `models/`, ни `vendor/`. Ресурс HACS добавит сам.
   Если ресурса нет — *Настройки → Панели → ⋮ → Ресурсы → Добавить*:
   ```
   URL:  /hacsfiles/Three.js-3D-Card/threejs-3d-card.js
   Тип:  JavaScript module
   ```
   Тот же адрес HACS прописывает сам, добавляя отметку версии `?hacstag=…` и
   обновляя её при выходе новой версии.
5. Обновите страницу (Ctrl+F5) и добавьте карточку на дашборд.

> Регистр в имени каталога — особенность HACS, а не требование карточки:
> однофайловая сборка самодостаточна, а раскладка `dist/` (вариант 2) подключает
> three.js и модели относительными путями и работает из любой папки.

### Вариант 2 — вручную

1. Возьмите из [релиза](https://github.com/IzerName/Three.js-3D-Card/releases)
   архив `threejs-3d-card.zip` (это содержимое `dist/` — та же карточка
   обычными ES-модулями) и распакуйте **всё** в
   `config/www/threejs-3d-card/`. Имя папки может быть любым; важно сохранить
   структуру: рядом с `threejs-3d-card.js` должны лежать каталоги `src/`,
   `models/` и `vendor/`.
2. *Настройки → Панели → ⋮ → Ресурсы → Добавить*:
   ```
   URL:  /local/threejs-3d-card/threejs-3d-card.js
   Тип:  JavaScript module
   ```
3. Перезагрузите страницу.

> ⚠️ Файлы, которые грузятся как ES-модули, должны отдаваться с корректным
> `Content-Type: text/javascript`. Home Assistant делает это автоматически
> для `/local/` и `/hacsfiles/`.

## Быстрый старт

Добавьте карточку (предпочтительно — через визуальный редактор, кнопка
«Добавить карточку» → «Three.js 3D Card»):

```yaml
type: custom:threejs-3d-card
model: water-tank
title: Бак чистой воды
height: 400
entities:
  level: sensor.water_preparation_level_clean_percentage
  liters: sensor.water_preparation_level_clean_liters
  counter: sensor.water_preparation_counter_clean_water
  high: binary_sensor.water_preparation_clean_high_sensor
  medium: binary_sensor.water_preparation_clean_medium_sensor
  low: binary_sensor.water_preparation_clean_low_sensor
params:
  full_value: 100
  max_liters: 200
  level_color: var(--color-2)
  probe_levels.high: 85
  probe_levels.medium: 50
  probe_levels.low: 25
```

Минимум, который нужен карточке — модель и одна-две привязки:

```yaml
type: custom:threejs-3d-card
model: water-tank
entities:
  level: sensor.water_level
```

Кнопка **«Показать редактор кода»** позволяет править YAML; визуальный
редактор строит те же поля автоматически.

## Встроенные модели

### `water-tank` — Бак чистой воды

Горизонтальный бак с водой, шкалой 0–100 %, тремя датчиками уровня,
счётчиком и подписью объёма.

| Ключ привязки | Домен | Обязательна | Что делает |
|---|---|---|---|
| `level` | `sensor`, `input_number`, `number` | **да** | Управляет уровнем воды |
| `liters` | те же | нет | Точный объём для подписи |
| `counter` | те же | нет | Счётчик внизу сцены |
| `high`, `medium`, `low` | `binary_sensor`, `input_boolean`, `switch` | нет | Светодиоды датчиков |

Параметры: `full_value` (значение, равное 100 %), `max_liters`, `level_color`,
`tank_radius`, `tank_length`, `wall`, `probe_levels.high|medium|low`.

### `production-room` — Производственное помещение

Вид сверху: ВРУ, счётчик воды, станок с вращающимся ротором, два диммируемых
источника света, пожарная сигнализация, обогреватель, кондиционер, дверь и
датчик освещённости. Привязки: `vru`, `water`, `water_flow`, `machine`,
`light1`, `light2`, `fire`, `heater`, `ac`, `door`, `lux`. Параметры: `width`,
`depth`, `height` помещения.

## Импорт своей модели

1. Положите файл модели в `config/www/3d-models/my-model.js`.
   Минимальный пример — в [docs/MODEL_API.md](docs/MODEL_API.md#1-быстрый-старт-минимальная-модель).
2. В редакторе карточки выберите **Модель → «Импортировать модель по URL…»**
   и укажите `/local/3d-models/my-model.js`.
3. Нажмите **Загрузить** — карточка прочитает файл, покажет его `bindings` и
   `params` и построит форму привязок.

Либо сразу в YAML:

```yaml
type: custom:threejs-3d-card
model: /local/3d-models/my-model.js
model_url: /local/3d-models/my-model.js
reload_model: true      # принудительно перечитать файл (обход кэша)
```

Модель обязана вызвать `window.ThreeJS3DCard.defineModel({...})` — полное
описание контракта, полей `bindings`/`params` и контекста `ctx` находится в
**[docs/MODEL_API.md](docs/MODEL_API.md)**.

## Конфигурация карточки

| Параметр | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `type` | string | — | `custom:threejs-3d-card` |
| `model` | string | `water-tank` | id встроенной модели или URL файла модели |
| `model_url` | string | — | Явный URL внешней модели (удобно для редактора) |
| `reload_model` | boolean | `false` | Читать файл модели заново (обход кэша браузера) |
| `allow_external_models` | boolean | `true` | Запретить импорт внешних моделей |
| `title` | string | из модели | Заголовок в HUD; пустая строка — скрыть |
| `show_hud` | boolean | `true` | Показывать заголовок |
| `height` | number | из модели | Высота карточки в пикселях |
| `entities` | object | — | Привязки: `ключ: entity_id` |
| `params` | object | из модели | Настройки модели (ключи как объявлены в модели) |
| `camera` | object | из модели | Переопределение камеры: `radius`, `phi`, `theta`, `target`, `minRadius`, `maxRadius` |
| `environment` | object | из модели | Переопределение окружения: `floor`, `background`, `shadows`, … |
| `show_diagnostics` | boolean | `false` | Показать панель диагностики привязок |

### Совместимость со старыми карточками

Конфигурации прежних проектов продолжают работать: карточка понимает
`type: custom:water-tank-card` и `type: custom:production-room-card` и
подставляет соответствующую модель. Плоские параметры (`full_value`,
`max_liters`, `width`, `depth`, …) в корне конфигурации тоже читаются.

## Редактор карточки

Визуальный редактор (шестерёнка на карточке) строится **из описания модели**:

| Блок | Что внутри |
|---|---|
| **Модель 3D-сцены** | Список встроенных моделей + «Импортировать модель по URL…». |
| **Оформление и поведение** | Заголовок, высота, HUD, диагностика, разрешение импорта моделей. |
| **Устройства и параметры** | Поля привязок (`ha-entity-picker` с фильтром) с живым значением сущности, сгруппированные как в модели. |
| **Настройки модели** | Поля `params` — числа, ползунки, флажки, цвета, списки. |
| **Вид камеры** | Дистанция, наклон, поворот, точка взгляда (если модель это допускает). |
| **Проверка привязок** | Итог: сколько заполнено, какие ошибки и предупреждения. |

**Добавление новой карточки.** Lovelace вызывает `getStubConfig(hass, entities)`
— карточка сама подбирает подходящие сущности (по `device_class`, единице
измерения и именам) и подставляет их в конфигурацию, чтобы сцена сразу
показывала данные.

## Управление из 3D

Клик по объекту сцены открывает окно сущности: состояние, атрибуты с
переводом подписей, время изменения и кнопки, соответствующие домену:

| Домен | Доступно |
|---|---|
| `switch`, `input_boolean`, `fan`, `humidifier`, `siren` | Включить / выключить |
| `light` | Включить / выключить, ползунок яркости |
| `climate` | Режимы `hvac_mode`, температура ±1° |
| `cover` | Открыть / стоп / закрыть |
| `lock` | Заблокировать / разблокировать |
| `button`, `script`, `automation` | Нажать / запустить |

Кнопка **«Открыть в Home Assistant»** отправляет событие `hass-more-info` —
открывается штатное окно сущности HA.

## Разработка

```bash
npm install          # three.js, terser, esbuild
npm run build        # собрать dist/ и однофайловый threejs-3d-card.js в корне
npm run serve        # локальный стенд: http://localhost:8099/dev/harness.html
npm test             # юнит- и интеграционные тесты (101 проверка)
npm run check        # сборка + тесты
npm run watch        # пересборка при изменении src/ и models/
```

Стенд `dev/harness.html` подменяет `hass.states` демо-состояниями: ползунок
уровня, переключатели датчиков, кнопка «сделать уровень недоступным» —
удобно проверять реакцию сцены и поведение редактора без Home Assistant.
Релиз стенд отдаёт по путям `/hacsfiles/threejs-3d-card/*` и
`/local/threejs-3d-card/*`, а однофайловую сборку — по
`/bundle/threejs-3d-card.js`; это адреса стенда, а не требование к установке.

Дополнительные страницы проверки (открываются с того же сервера):

| Страница | Что проверяет |
|---|---|
| `dev/probe-bundle.html` | **Однофайловая сборка** — ровно тот файл, который ставит HACS: загрузка как модуля, регистрация элементов, публикация API с отметкой `bundled`, three.js из бандла (r160), ноль запросов к `vendor/`, `src/` и `models/`, построение сцены, отрисовка кадров, переподключение карточки. |
| `dev/probe.html` | Полный сценарий: построение сцены, привязки, модалка сущности, переход в HA, импорт модели по URL, переключение моделей, редактор. |
| `dev/probe-ext.html` | Импорт внешней модели по URL и её отрисовка. |
| `dev/probe-render.html` | Что обе модели действительно рисуют кадры и не теряют WebGL-контекст. |
| `dev/probe-obj.html` | Объектная модель из OBJ/MTL: имена объектов, цвет по состоянию и по числу, светильник, дверь (петля), вентилятор, текст, редактор. |
| `dev/probe-glb.html`, `dev/probe-gltf.html` | Загрузка GLB и glTF (с внешним `.bin`) через карточку. |

Отчёты этих страниц складываются в `dev/report.json`. Прогнать страницу в
headless Chrome в реальном времени (нужно для проверок, которые зависят от
кадров: плавная смена цвета, разгорание лампы):

```bash
node dev/probe-runner.mjs http://127.0.0.1:8099/dev/probe-bundle.html 25000
node dev/probe-runner.mjs http://127.0.0.1:8099/dev/probe-obj.html 30000
```

> Флаг `--virtual-time-budget` для таких страниц не подходит: время вперёд не
> идёт, `requestAnimationFrame` не успевает продвинуть анимацию, и проверки
> цвета/света падают на исправном коде.

`npm run build` собирает из одних исходников **две раскладки**, и обе обязаны
работать одинаково:

* `threejs-3d-card.js` в корне репозитория — **однофайловая сборка** (esbuild):
  внутри three.js r160, загрузчики OBJ/MTL/glTF, ядро карточки и встроенные
  модели, около 911 КБ. Именно её ставит HACS;
* `dist/` — та же карточка обычными ES-модулями (`dist/threejs-3d-card.js` +
  `src/`, `models/`, `vendor/`). Её отдаёт стенд, и она же уходит в архив
  `threejs-3d-card.zip` для ручной установки. Бандлер здесь не нужен: исходники
  видны в браузере как есть, с именами файлов и строками.

### Выпуск релиза

1. Обновите `version` в `package.json` и `CARD_VERSION` в
   `src/core/constants.js`, допишите `CHANGELOG.md`.
2. Выполните `npm run build` и закоммитьте обновлённые `dist/` **и корневой
   `threejs-3d-card.js`** — HACS ставит файлы прямо из тега и ничего не
   собирает.
3. Создайте тег `vX.Y.Z` и запушьте его — GitHub Actions
   ([.github/workflows/release.yml](.github/workflows/release.yml)) прогонит
   тесты, пересоберёт обе раскладки, проверит, что закоммиченные `dist/` и
   бандл совпадают со сборкой (`git diff --exit-code -- dist threejs-3d-card.js`),
   и приложит `threejs-3d-card.zip` к
   [релизу](https://github.com/IzerName/Three.js-3D-Card/releases).
4. HACS увидит новый релиз и предложит обновление; ресурс переустанавливать не
   нужно — HACS обновляет отметку `?hacstag=…` сам.

Подробнее — [docs/HACS.md](docs/HACS.md).

## Диагностика проблем

| Симптом | Что делать |
|---|---|
| «Не удалось загрузить three.js» | В однофайловой сборке three.js внутри файла — проверьте, что ресурс указывает на целый `threejs-3d-card.js`. При установке из архива `dist/` проверьте, что каталог `vendor/` распакован рядом с карточкой. Либо разрешите доступ к `cdn.jsdelivr.net` (карточка пробует CDN как резерв). |
| «Модель … не найдена» | Проверьте id модели в редакторе; для своей модели — путь `/local/3d-models/…`. |
| «Модель … не вызвала defineModel(…)» | Файл модели не является моделью threejs-3d-card или упал до вызова `defineModel`. Откройте консоль браузера (F12). |
| `NotSupportedError: Shadow root cannot be created…` | Так падала версия 0.1.0 при переподключении элемента Lovelace — в 0.1.1 исправлено: обновите файл карточки и страницу (Ctrl+F5). |
| Сцена пустая, ошибок нет | Включите `show_diagnostics: true` — панель покажет незаполненные и недоступные привязки. |
| Сущность «не найдена» в редакторе | Опечатка в `entity_id`, другая панель/интеграция или сущность удалена. |
| Карточка тормозит | Отключите `shadows` в `environment`, уменьшите `height`, не ставьте больше 3–4 3D-карточек на один дашборд. |
| Пропала 3D-сцена после переключения вкладок | Карточка освобождает WebGL-контекст при удалении и создаёт заново. Если сцена не вернулась — обновите страницу и сообщите об ошибке. |

Полезно в консоли браузера:

```js
ThreeJS3DCard.models();                                 // загруженные модели
document.querySelector("threejs-3d-card")._engine.diagnostics();
```

## Безопасность

* Внешняя модель — это **JavaScript, исполняемый в вашем Home Assistant** с
  правами вашей сессии. Загружайте только свои файлы или файлы из источников,
  которым доверяете. При необходимости запретите импорт:
  `allow_external_models: false`.
* Карточка не запрашивает и не хранит токены доступа: она работает через
  штатный объект `hass` уже авторизованного интерфейса.
* Управление выполняется только штатными сервисами Home Assistant
  (`hass.callService`), прав доступа карточка не расширяет.

├─ package.json                 сборка, тесты, локальный стенд
├─ dist/                        раскладка из ES-модулей: стенд и ручная установка
│  ├─ threejs-3d-card.js        точка входа (ресурс Lovelace)
│  ├─ src/  models/             ядро и модели — то же, что в исходниках
│  └─ vendor/                   three.js r160 + загрузчики OBJ/MTL/glTF
├─ src/                         исходники карточки
│  ├─ card.js                   карточка <threejs-3d-card>

│     ├─ state.js               шина состояний hass.states
│     ├─ registry.js            реестр моделей и загрузка внешних моделей
│     ├─ object-model.js        объектная модель из спецификации (OBJ/MTL, glTF)
│     ├─ object-rules.js        движок декларативных правил
│     ├─ geometry.js            загрузка геометрии: OBJ+MTL, glTF/GLB
│     ├─ three-loader.js        three.js: из бандла, локально или CDN
│     ├─ stub.js                getStubConfig: подбор сущностей
│     ├─ styles.js              стили оверлея (тема HA)
│     └─ util.js                вспомогательные функции
├─ models/
│  ├─ water-tank/               модель «Бак чистой воды»

├─ docs/

│  ├─ OBJECT_MODEL.md           декларативный формат объектной модели

`dist/` и корневой `threejs-3d-card.js` собираются из `src/` и `models/` скриптом
`scripts/build.mjs` и коммитятся: HACS для Dashboard-плагина ищет `filename` в
корне репозитория и скачивает только корневые `.js` — поэтому там лежит
однофайловая сборка, которой на сервере больше ничего не нужно. Раскладка `dist/`
остаётся для стенда и архива ручной установки (подробнее —
[docs/HACS.md](docs/HACS.md)).
