# Публикация репозитория в HACS

Короткая инструкция для того, кто форкает или форкает и развивает этот проект.
Полная документация HACS — <https://hacs.xyz/docs/publish/start>.
Репозиторий проекта — <https://github.com/IzerName/Three.js-3D-Card>
(ветка по умолчанию — `main`).

---

## 1. Что обязательно должно быть в репозитории

```
<repo-root>/
├─ hacs.json                    ← манифест, ОБЯЗАТЕЛЕН
├─ README.md                    ← описание (HACS показывает его в карточке)
├─ LICENSE
├─ threejs-3d-card.js           ← ОДНОФАЙЛОВАЯ сборка: файл из hacs.json (filename)
│                                 её HACS скачивает и подключает ресурсом
├─ dist/                        ← та же карточка обычными ES-модулями
│  ├─ threejs-3d-card.js        ← точка входа раскладки: дев-стенд
│  ├─ src/                      ← ядро карточки, редактор, объектные модели
│  ├─ models/                   ← встроенные модели (water-tank, production-room)
│  └─ vendor/                   ← three.js r160 + загрузчики OBJ/MTL/glTF
├─ src/  models/                ← исходники (в поставку пользователю не попадают)
├─ scripts/build.mjs            ← сборка: dist/ и корневой threejs-3d-card.js
└─ test/  dev/  docs/  skills/  ← тесты, стенд, документация, скилл агента
```

Корневой `threejs-3d-card.js` **закоммичен**: HACS берёт файл из дерева тега
по `filename` из `hacs.json` и ничего не собирает — нет файла в теге, ставить
будет нечего. `dist/` коммитится тоже: его отдаёт дев-стенд, и CI сверяет обе
раскладки с результатом сборки.

`hacs.json` этого проекта:

```json
{
  "name": "Three.js 3D Card",
  "filename": "threejs-3d-card.js",
  "render_readme": true,
  "homeassistant": "2023.9.0"
}
```

| Поле | Смысл |
|---|---|
| `name` | Имя, которое увидит пользователь в HACS. |
| `filename` | **Ключевое поле для Dashboard-плагина:** файл, который HACS подключит ресурсом. HACS ищет его в корне дерева тега и скачивает только корневые `.js` — поэтому в корне лежит однофайловая сборка. |
| `render_readme` | Рендерить README в карточке HACS (`true`). |
| `homeassistant` | Минимальная версия HA (HACS покажет предупреждение на более старых). |

> Ключа `contentdir` в HACS **не существует** — его нет в исходниках
> `hacs/integration`. Полный список известных HACS ключей: `content_in_root`,
> `country`, `filename`, `hacs`, `hide_default_branch`, `homeassistant`,
> `manifest`, `name`, `persistent_directory`, `render_readme`, `zip_release`.
> Незнакомые ключи игнорируются, поэтому каталог релиза задаёт не манифест, а
> раскладка репозитория.

### Почему в корне лежит один файл

HACS для Dashboard-плагина берёт файл из дерева тега по `filename` из
`hacs.json` — из корня скачивает **только корневые `.js`**. Важная особенность
(проверено по исходникам HACS, `hacs/integration`): если у релиза на теге
**есть хотя бы один файловый ассет**, HACS скачивает **все ассеты** и кладёт
их как есть в `config/www/community/<репозиторий>/` — архивы не распаковывает
(распаковка — только при `zip_release: true` в `hacs.json`) — и в дерево тега
при этом не заглядывает. Именно так в 0.1.2 в `www/community/` попадал только
zip-ассет, а сам файл карточки не скачивался.

Поэтому релиз публикуется **без файловых ассетов**, а в корне репозитория
лежит однофайловая сборка: тогда HACS скачает именно её. Однофайловый режим —
штатный для HACS и предсказуемый.

`npm run build` собирает релиз в двух видах из одних исходников:

| Раскладка | Что это | Кому нужна |
|---|---|---|
| `threejs-3d-card.js` в корне | однофайловая сборка (esbuild): three.js r160, загрузчики OBJ/MTL/glTF, ядро карточки и встроенные модели внутри, ~1 МБ | HACS: файл из `hacs.json` |
| `dist/` | `threejs-3d-card.js` + `src/`, `models/`, `vendor/` — обычные ES-модули, без бандлера | дев-стенд (`npm run serve`); закоммичена, CI сверяет с результатом сборки |

Обе раскладки обязаны работать одинаково, и обе коммитятся. Проверяет это CI:
после `npm run build` он падает, если `git diff --exit-code -- dist
threejs-3d-card.js` показывает расхождение.

### Что окажется на сервере

| Что | Значение |
|---|---|
| Каталог установки | `config/www/community/Three.js-3D-Card/` — имя репозитория **как есть, с регистром** |
| Содержимое | один файл `threejs-3d-card.js` — однофайловая сборка; ни `src/`, ни `models/`, ни `vendor/` рядом не нужно |
| Ресурс Lovelace | `/hacsfiles/Three.js-3D-Card/threejs-3d-card.js?hacstag=…`, тип **JavaScript module** |

Каталог называется так из-за регистра имени репозитория. Абсолютных путей к
ядру в карточке нет: three.js и загрузчики форматов подключаются литеральными
относительными импортами (`import("../../vendor/three.module.js")` в
`src/core/three-loader.js`, загрузчики OBJ/MTL/glTF — в `src/core/geometry.js`).
В однофайловой сборке esbuild подставляет их внутрь файла, в раскладке `dist/`
те же пути работают по сети. Поэтому одна и та же карточка работает и из
`config/www/community/Three.js-3D-Card/`, и из `/local/<любая-папка>/`.

## 2. Релизы

HACS предлагает пользователю **последний релиз** репозитория.

1. Обновите версию:
   * `package.json` → `"version": "X.Y.Z"`;
   * `src/core/constants.js` → `CARD_VERSION = "X.Y.Z"`;
   * допишите `CHANGELOG.md`.
2. Пересоберите и закоммитьте обе раскладки:
   ```bash
   npm run build
   git add dist threejs-3d-card.js
   git commit -m "build: dist и бандл для vX.Y.Z"
   ```
   Без этого шага в теге окажется старый (или отсутствующий) бандл — HACS
   скачает именно то, что лежит в теге, а не то, что собирается в CI.
3. Поставьте тег и запушьте:
   ```bash
   git tag vX.Y.Z
   git push origin main --tags
   ```
4. Workflow `.github/workflows/release.yml` по тегу `v*` выполняет `npm test` —
   в нём `test/publish.test.js` падает, если раскладка для HACS разошлась с
   исходниками, — затем `npm run build` и проверку, что закоммиченные `dist/` и
   корневой бандл совпадают со сборкой (`git diff --exit-code -- dist
   threejs-3d-card.js`). GitHub-релиз публикуется **без файловых ассетов** —
   HACS скачает корневой `threejs-3d-card.js` из дерева тега.
5. Ручная установка — однофайловый `threejs-3d-card.js` из тега: возьмите
   [исходник файла](https://github.com/IzerName/Three.js-3D-Card/blob/v0.1.3/threejs-3d-card.js)
   ([релиз v0.1.3](https://github.com/IzerName/Three.js-3D-Card/releases/tag/v0.1.3)),
   положите его в `config/www/threejs-3d-card/` и добавьте ресурс
   `/local/threejs-3d-card/threejs-3d-card.js` типа **JavaScript module**.
   Имя папки может быть любым — карточка к нему не привязана.

## 3. Установка «как у пользователя» (обязательная проверка перед релизом)

1. HACS → **Frontend** → ⋮ → **Custom repositories** → URL
   `https://github.com/IzerName/Three.js-3D-Card` → категория **Dashboard**.
2. Найти карточку → **Download**.
3. Проверьте результат — должно появиться **и то, и другое**:
   * на сервере: `config/www/community/Three.js-3D-Card/` с **одним файлом**
     `threejs-3d-card.js` (это однофайловая сборка; `src/`, `models/` и
     `vendor/` рядом не требуются);
   * в *Настройки → Панели → ⋮ → Ресурсы*: ресурс
     `/hacsfiles/Three.js-3D-Card/threejs-3d-card.js?hacstag=…` типа
     **JavaScript module** (`?hacstag=…` — служебная отметка версии).
   Если HACS ресурс не добавил — добавьте вручную тот же URL без `?hacstag=…`
   и перезагрузите страницу.
4. Добавьте карточку через UI: «Добавить карточку» → **Three.js 3D Card**.
   Должны выполниться все четыре условия:
   * карточка появилась в списке (значит `getConfigElement` отработал);
   * в редакторе есть поля выбора устройств (значит модель загрузилась,
     `bindings` прочитаны);
   * 3D-сцена рисуется, привязки показывают живые значения;
   * камера управляется и мышью (ЛКМ — вращение, ПКМ — сдвиг, колесо — зум,
     двойной клик — сброс вида), и касаниями (один палец — вращение, два
     пальца — зум и сдвиг, двойной тап — сброс вида).
   Отдельно убедитесь, что карточка работает, когда рядом с ней нет ни `src/`,
   ни `models/`, ни `vendor/` — именно так выглядит установка из HACS. На стенде
   это проверяет `dev/probe-bundle.html` (бандл отдаётся по
   `/bundle/threejs-3d-card.js`).
5. Обновите версию в HACS — убедитесь, что обновление проходит без
   переустановки ресурса: HACS сам меняет отметку `?hacstag=…` у уже
   добавленного ресурса.

## 4. Частые причины отказа HACS

| Симптом | Причина |
|---|---|
| «Repository structure for … is not compliant» | Нет `hacs.json` или нет `threejs-3d-card.js` в корне тега: бандл не собран или не закоммичен (`npm run build`, `git add threejs-3d-card.js`). |
| Ресурс есть, но файл не отдаётся (404) | URL ресурса указывает на другой каталог: HACS отдаёт плагин по имени репозитория как есть — `/hacsfiles/Three.js-3D-Card/…`, регистр важен. |
| Карточка есть, но не грузится | Файл добавлен ресурсом с типом «JavaScript» вместо «JavaScript module». |
| «Custom element doesn't exist» | Браузер держит старую версию — очистите кэш (Ctrl+F5) или обновите ресурс с `?v=`. |
| 3D-сцена не появляется, ошибка про three.js | HACS-установка: проверьте, что скачался целый `threejs-3d-card.js` (three.js внутри него), — то же самое для ручной установки файла из тега. |
| Модели не находятся | Встроенные модели лежат внутри бандла (HACS — корневой файл, ручная установка — файл из тега): если их нет, скачался обрезанный или чужой файл. |
| Обновление не подхватилось | HACS обновляет `?hacstag=…` у существующего ресурса, но браузер держит старый файл — нужен Ctrl+F5. |

## 5. Локальная проверка перед публикацией

```bash
npm install
npm run check      # сборка (dist/ + бандл) + все тесты
npm run serve      # стенд: http://localhost:8099/dev/harness.html
```

Отдельно раскладку для HACS проверяют два файла тестов:
`test/publish.test.js` (в корне репозитория ровно один `.js` — бандл; `dist/`
закоммичен; аддоны в `dist/` импортируют three относительным путём) и
`test/bundle.test.js` (однофайловая сборка: нет относительных импортов,
элементы регистрируются, `window.ThreeJS3DCard` публикуется с отметкой
`bundled: true`, three.js поднимается из бандла, встроенные модели доступны).

Стенд отдаёт релиз по `/hacsfiles/threejs-3d-card/*` — это префикс **стенда**
(страницы `dev/probe-*.html` написаны под него), а не тот путь, по которому
карточка окажется на сервере Home Assistant. Однофайловая сборка отдаётся по
`/bundle/threejs-3d-card.js` (страница `dev/probe-bundle.html`), вариант ручной
установки — по `/local/threejs-3d-card/*`.

Проверьте на стенде: сцену, редактор (кнопка «Показать конфигурацию»),
`getStubConfig()` и переключение моделей. Затем — установка на тестовом
Home Assistant по шагам из раздела 3.
