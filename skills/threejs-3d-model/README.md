# Скилл `threejs-3d-model`

Готовый набор инструкций для агента (Claude Code, DSH, любой агент, читающий
каталог навыков): по словесной просьбе он собирает работающую 3D-модель для
карточки [threejs-3d-card](../../README.md) — спецификацию в JSON (обёртка в JS
нужна только для расширения кодом), при необходимости — готовый файл модели —
и инструкцию по установке. Пользователю не нужно писать код.

## Что внутри

| Файл | Зачем |
|---|---|
| `SKILL.md` | инструкция агенту: порядок работы, жёсткие правила, типовые случаи, чего делать нельзя |
| `reference/SPEC.md` | полный справочник формата: все поля, адресация объектов, действия, условия |
| `scripts/validate-model.mjs` | валидатор спецификации (Node.js, без зависимостей) |
| `examples/room.json`, `room.js`, `room.obj`, `room.mtl` | рабочий пример: комната с лампой, дверью, вентилятором и датчиком температуры |

## Установка

Скилл — это каталог с `SKILL.md` в корне. Скопируйте каталог целиком туда, где
ваш агент ищет навыки:

| Агент | Куда копировать |
|---|---|
| Claude Code | `~/.claude/skills/threejs-3d-model` (в проекте — `.claude/skills/threejs-3d-model`) |
| DSH | каталог, откуда агент читает навыки проекта (в этом репозитории — `skills/`) |
| Другой агент | в его каталог навыков; главное — `SKILL.md` в корне каталога скилла |

```powershell
# Windows, из корня репозитория threejs-3d-card
Copy-Item -Recurse skills\threejs-3d-model $env:USERPROFILE\.claude\skills\
```

```bash
# Linux/macOS
cp -r skills/threejs-3d-model ~/.claude/skills/
```

После копирования агент находит скилл по описанию в `SKILL.md` (там перечислены
триггеры: «сделай 3D-модель для Home Assistant», «подключи датчики к 3D-модели»,
«оживи модель дома», «сделай цифрового двойника»).

## Как пользоваться

Напишите агенту словами, что должно быть на модели и что с чем связано.
Минимум, который стоит указать:

* **файл модели** — есть ли готовый (`OBJ`/`MTL` или `GLB`) и по какому он URL
  (`/local/3d/house.glb`); файл можно загрузить в редакторе карточки и
  ссылаться через `model_assets` (тогда он живёт в хранилище браузера, см.
  `docs/CONFIGURATION.md`); если файла нет — попросите сгенерировать простую
  модель;
* **сущности Home Assistant** — список `entity_id`, которые должны влиять на
  модель (`light.kitchen`, `binary_sensor.front_door`, `sensor.power`);
* **что должно происходить** — цвет, скрытие, подсветка, вращение, открывание
  двери, текст состояния, проигрывание анимации из файла (GLB из Blender,
  действие `play`);
* **пометки в файле** — если glTF/GLB экспортирован из Blender с
  кастомными свойствами `t3d_*`, список привязок указывать не нужно:
  карточка прочитает его из самого файла (рецепт — `docs/OBJECT_NAMES.md` §2).

Пример просьбы:

> Сделай 3D-модель для карточки threejs-3d-card. Модель: `/local/3d/house.obj`
> (файл уже лежит, сантиметры). Нужно: `light.kitchen` — включает лампу
> `Lamp_Kitchen` (цвет и подсветка); `binary_sensor.front_door` — открывает
> створку `Door_Front`; `sensor.outdoor_temp` — пишет температуру на панель
> `Label_Temp`.

Если чего-то не хватает, агент задаст не больше трёх вопросов или сделает
явное предположение и продолжит.

### Просьба → что делает агент

| Просьба | Что делает агент |
|---|---|
| «Лампа должна светиться, когда включено» | Привязка с `colors: { on, off }` и `light: { lumens }` к объекту лампы |
| «Показывать, открыта ли дверь» | `door: { hinge, degrees, open }` на створку двери |
| «Вентилятор должен крутиться» | `rotate: { axis, round_per_second }` на объект вентилятора |
| «Скрыть датчик, когда он недоступен» | `hide: ["off", "unavailable"]` |
| «Показать температуру цифрами» | `text: { template: "{value} {unit}" }` на панель подписи |
| «Красить индикатор по уровню» | `colors` с условиями `">=30"` / `"<10"` или градиент `scale` |
| «Несколько деталей по одной сущности» | `target: ["Lamp_1", "Lamp_2"]` или `groups` + `target: "@lamps"` |
| «Модель в сантиметрах (Sweet Home 3D)» | `source.scale: 0.01` |
| «Модель не влезает в карточку / висит в воздухе» | `source.fitSize`, `center: true`, `ground: true` |
| «Не знаю имён объектов в модели» | Даёт фрагмент для консоли браузера (`docs/OBJECT_NAMES.md`) и просит прислать вывод |
| «Анимация из Blender запускается по состоянию» | `play: { clip: "<имя клипа>", on: ["on"] }` на анимируемый объект — клип и объекты должны быть названы (подробно — `reference/SPEC.md` §6.7) |
| «Спецификация не нужна, если пометки есть в файле» | Минимальная спека с `bindingsFrom: { gltfExtras: true }` — привязки читаются из пометок `t3d_*` в glTF/GLB (рецепт Blender — `docs/OBJECT_NAMES.md` §2) |
| «Своей 3D-модели нет» | Генерирует простой OBJ (пол, лампа, дверь, вентилятор) и привязки к нему |
| «Нужна своя анимация, спецификации мало» | Пишет модуль модели с `create(ctx)` (`docs/MODEL_API.md`) |

### Что вы получите

1. `<id>-model.json` — спецификация (её правит пользователь, не агент);
   карточка загружает её напрямую, без обёртки: `model: /local/3d/<id>-model.json`
   или `model: asset:<id>-model.json`, если файл загружен в редакторе;
2. при необходимости `<id>-model.js` — обёртка с расширением кодом
   (`create(ctx)`, `docs/MODEL_API.md`);
3. при необходимости `<id>-model.obj` — сгенерированная геометрия;
4. короткую инструкцию: куда положить файлы (`config/www/3d/` → `/local/3d/…`)
   и какую конфигурацию вписать в карточку.

## Проверка результата

Спецификацию обязательно прогоняют валидатором (нужен Node.js):

```bash
node skills/threejs-3d-model/scripts/validate-model.mjs путь/к/house-model.json
```

```
✔ house-model.json

  файлов: 1, ошибок: 0, предупреждений: 0
  спецификация корректна
```

Валидатор различает ошибки (спецификация нерабочая) и предупреждения
(сработает, но не так, как ожидается):

* **ошибки:** опечатки в названиях действий (`action: "colour"`), пустые
  `target` и `entity`, отсутствие `manifest.id`, недопустимые значения
  (`rotate.axis: "q"`, `params[].type: "unknown-type"`);
* **предупреждения:** неизвестные поля (`colours`, `source.scaleX`), привязка
  без единого действия, `door.slide` вместе с `degrees` без `span`, блок
  `entityConfig` для сущности, которой нет в `bindings`.

Можно передать каталог — проверятся все `*.json` в нём. Флаги: `--json`
(машинный итог, вместе с `--quiet` — чистый JSON), `--quiet` (без построчного
разбора). Код возврата `1`, если есть ошибки, — команду можно ставить в CI.

Дополнительно: имена объектов модели удобно сверить с реальной сценой
фрагментом из `docs/OBJECT_NAMES.md`, а результат работы карточки — включив в её
конфигурации `show_diagnostics: true`.

## Известные расхождения

* `SKILL.md` ссылается на примеры `examples/machine.json` и `machine.js` — в
  каталоге `examples/` сейчас только `room.*`. Если нужен пример «станок»,
  агент соберёт его по `reference/SPEC.md` с нуля.
* Скилл описывает загрузку glTF/GLB; самопроверки загрузчика —
  `dev/probe-glb.html` и `dev/probe-gltf.html` в репозитории карточки.
* Валидатор не знает действие `play`: краткая запись `play: {…}` даёт
  предупреждения «неизвестное поле» и «нет ни одного действия», а запись
  `actions: [{ action: "play" }]` — ошибку с перечнем шести известных
  действий. Спецификацию с `play` пока проверяйте без соответствующей
  привязки (остальные поля валидатор знает).
