## 1. Структура файлов

Кладут в `config/www/3d/` на сервере Home Assistant:

```
config/www/3d/
├─ house.json          ← спецификация (данные)
├─ house.js            ← обёртка (3-8 строк)
├─ house.obj           ← файл модели
├─ house.mtl           ← материалы (если есть)
└─ textures/           ← текстуры, если на них ссылается MTL
```

Доступны по URL `/local/3d/...`.

**Обёртка** (`house.js`) — обязательна, потому что карточка подключает модели
как JavaScript-модули:

```js
// /local/3d/house.js
// Ядро карточки берём из её глобального API — каталог установки знать не нужно.
const { createObjectModel } = window.ThreeJS3DCard;

const spec = await fetch("/local/3d/house.json").then((r) => r.json());
export default createObjectModel(spec);
```

Вариант без отдельного JSON — спецификация прямо в модуле:

```js
const { createObjectModel } = window.ThreeJS3DCard;

export default createObjectModel({
  manifest: { id: "house", name: "Мой дом" },
  source: { url: "/local/3d/house.obj", mtl: "/local/3d/house.mtl" },
  bindings: [ /* … */ ],
});
```

> `window.ThreeJS3DCard` создаёт сам ресурс карточки, поэтому обёртка не
> зависит от каталога установки: через HACS карточка лежит под
> `/hacsfiles/<имя-репозитория>/…`, при ручной установке — под
> `/local/<любая-папка>/…`. Вариант с `import` тоже работает, но путь
> придётся подставить под свою установку: например
> `/local/threejs-3d-card/src/core/object-model.js`.

**Конфигурация карточки:**

```yaml
type: custom:threejs-3d-card
model: /local/3d/house.js
title: Мой дом
height: 620
entities:
  light.kitchen: light.kitchen     # ключ = entity_id из спецификации
```

## 2. manifest

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | **да** | Уникальный идентификатор модели (латиница, цифры, `_`, `-`). |
| `name` | string | нет | Название в списке моделей редактора. |
| `description` | string | нет | Пояснение. |
| `camera` | object | нет | Начальный вид: `target [x,y,z]`, `radius`, `phi`, `theta`. Если не задан — карточка ставит камеру автоматически по габаритам модели. |
| `environment` | object | нет | `floor: "none"｜"radial"｜"plane"｜"grid"`, `background`, `shadows`. |
| `size` | object | нет | `{ defaultHeight, minHeight, maxHeight }` — рекомендуемая высота карточки. |

## 3. source — файл модели

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `url` | string | **да** | Путь к файлу: `/local/3d/house.obj`, `/local/3d/house.glb`. |
| `format` | string | нет | `obj` или `gltf`. Определяется по расширению, если не указан. `.glb` и `.gltf` — одно и то же значение. |
| `mtl` | string | нет | Файл материалов для OBJ. По умолчанию — одноимённый `.mtl`. Если файла нет, модель загрузится со стандартным материалом (будет предупреждение). |
| `scale` | number | нет | Множитель размера. **Для сантиметровых моделей — `0.01`.** |
| `fitSize` | number | нет | Вписать модель в куб такого размера (в метрах), сохранив пропорции. Взаимоисключим со `scale`. |
| `center` | boolean | нет | Центрировать по X/Z (по умолчанию `true`). |
| `ground` | boolean | нет | Опустить на `y = 0` (по умолчанию `true`). |
| `dracoPath` | string | нет | Путь к декодеру Draco (`/local/draco/`), если GLB сжат. Декодер в поставку не входит. |
| `normalize` | boolean | нет | `false` — не трогать положение и масштаб модели вообще. |

Автоматическое «приведение к полу и центру» включено намеренно: без него
модели из Blender/Sweet Home 3D оказываются за пределами видимости камеры.

## 4. bindings — привязки сущностей

Массив. Один элемент = одна сущность Home Assistant и то, что она делает с
объектами модели.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `entity` | string | **да** | `entity_id` Home Assistant (`light.kitchen`). Он же — ключ в `entities` карточки. |
| `target` | string \| string[] | **да** | Имя объекта (или объектов) модели. См. раздел 5. |
| `name` | string | нет | Подпись в редакторе карточки. |
| `group` | string | нет | Группа полей в редакторе. |
| `colors` | object | нет | Цвет по состоянию: `{ "on": "#ffd9a0", "off": "#3a3a3a" }`. См. раздел 7. |
| `hide` | string \| string[] | нет | Состояния, при которых объект **скрыт**: `["off", "closed"]`. |
| `light` | object | нет | Подсветка (см. 6.3). |
| `rotate` | object | нет | Вращение (см. 6.4). |
| `door` | object | нет | Дверь/окно (см. 6.5). |
| `text` | object | нет | Подпись состояния (см. 6.6). |
| `actions` | array | нет | Несколько действий в одной привязке: `[{ action: "color", colors: {…} }, { action: "hide", hideWhen: ["off"] }]`. |
| `rate` | number | нет | Скорость сглаживания (по умолчанию 6). Больше — резче реакция. |

Краткая запись «одно действие» и полная через `actions` эквивалентны:

```json
{ "entity": "light.kitchen", "target": "Lamp_Kitchen", "colors": { "on": "#ffd9a0" } }
```

```json
{ "entity": "light.kitchen", "target": "Lamp_Kitchen",
  "actions": [{ "action": "color", "colors": { "on": "#ffd9a0" } }] }
```

### Названия действий

| Действие | Краткий ключ | Полная форма |
|---|---|---|
| Цвет | `colors` \| `color` | `{ action: "color", … }` |
| Видимость | `hide` | `{ action: "hide", … }` |
| Подсветка | `light` | `{ action: "light", … }` |
| Вращение | `rotate` | `{ action: "rotate", … }` |
| Дверь | `door` | `{ action: "door", … }` |
| Текст | `text` | `{ action: "text", … }` |

## 5. Адресация объектов (target)

Имена объектов берутся из файла модели: в OBJ это группы `o <Имя>`
(или `g <Имя>`), в glTF — имена узлов.

| Форма | Пример | Что найдёт |
|---|---|---|
| Точное имя | `"Lamp_Kitchen"` | Один объект. Регистр не важен. |
| Массив | `["Lamp_1", "Lamp_2"]` | Несколько конкретных объектов. |
| Шаблон | `"Lamp_*"` | Все объекты, подходящие под шаблон (`*` — любые символы, `?` — один). |
| Регулярка | `"/^Lamp_/"` | Все объекты по регулярному выражению. |
| Группа | `"@lamps"` | Объекты из блока `groups` (см. ниже). |

```json
{
  "groups": {
    "lamps": ["Lamp_Kitchen", "Lamp_Hall"],
    "windows": ["/^Window_/"]
  },
  "bindings": [
    { "entity": "light.all", "target": "@lamps", "colors": { "on": "#fff2c0" } }
  ]
}
```

**Правила именования деталей модели** (чтобы привязки были понятны человеку):

| Тип детали | Шаблон имени | Пример |
|---|---|---|
| Лампа/светильник | `Lamp_<Место>` | `Lamp_Kitchen` |
| Дверь (створка) | `Door_<Место>` | `Door_Front` |
| Петля/рама двери | `Door_<Место>_Hinge` | `Door_Front_Hinge` |
| Окно | `Window_<Место>` | `Window_Living` |
| Вентилятор | `Fan_<Место>` | `Fan_Bathroom` |
| Датчик | `Sensor_<Что>` | `Sensor_Temp` |
| Прибор/станок | `Device_<Имя>` | `Device_Press` |
| Панель под текст | `Label_<Что>` | `Label_Temp` |

## 6. Действия

### 6.1 Цвет — `colors` / `color` / `{ action: "color" }`

| Поле | Тип | Описание |
|---|---|---|
| `colors` | object | Таблица «состояние → цвет». Ключи — состояния (`"on"`) или условия (`">=30"`). |
| `color` | string | Один цвет без условий — применяется всегда (например, лёгкий оттенок). |
| `conditions` | array | `[{ "condition": ">=30", "color": "#ff0000" }, …]` — проверяются по порядку. |
| `scale` | object | Градиент по числу: `{ "from": { "min": 0, "max": 100 }, "colors": ["#0f0","#ff0","#f00"] }`. |
| `restore` | boolean | `false` — не возвращать исходный цвет модели, когда ни одно условие не совпало (по умолчанию `true`). |
| `rate` | number | Скорость перехода цвета. |

Если ни одно условие не совпало и `restore` не `false` — объект плавно
возвращается к цвету из файла модели.

Цвет задаётся как `#rrggbb`, `rgb(r,g,b)` или CSS-переменная темы
`var(--primary-color)`.

### 6.2 Видимость — `hide` / `{ action: "hide" }`

| Поле | Тип | Описание |
|---|---|---|
| `hide` | string \| string[] \| true | Состояния, при которых объект скрыт. `true` — скрывать при `off/closed/unavailable/unknown`. |
| `showWhen` | string \| string[] | Наоборот: показывать только в этих состояниях. |
| `hideWhen` | string \| string[] | Синоним `hide` в полной форме. |

Скрытый объект не участвует в кликах (raycaster его не видит).

### 6.3 Подсветка — `light` / `{ action: "light" }`

| Поле | Тип | По умолч. | Описание |
|---|---|---|---|
| `lumens` | number | `800` | Световой поток. Влияет на яркость источника. |
| `color` | string | `#fff6e0` | Цвет света (можно `var(--…)`). |
| `distance` | number | `0` | Радиус действия в метрах; `0` — без ограничения. |
| `decay` | number | `2` | Затухание (физически корректное — 2). |
| `useBrightness` | boolean | `true` для `light.*` | Учитывать атрибут `brightness` (0…255) при яркости. |
| `valueMax` | number | — | Если яркость задаётся числовым состоянием, значение, соответствующее 100 %. |
| `offset` | [x,y,z] | — | Смещение источника от центра объекта. |
| `castShadow` | boolean | `false` | Отбрасывать тени (нужен `environment.shadows: true`). |
| `on` | string \| string[] | `["on","open"]` | Состояния «включено». |

Подсветка = реальный источник света + свечение (`emissive`) материала, поэтому
объект выглядит включённым, даже если вокруг светло.

### 6.4 Вращение — `rotate` / `{ action: "rotate" }`

| Поле | Тип | По умолч. | Описание |
|---|---|---|---|
| `axis` | `"x"｜"y"｜"z"` | `"y"` | Ось вращения. Для вентилятора на стене — `"z"`. |
| `round_per_second` | number | `1` | Оборотов в секунду. |
| `direction` | `"forward"｜"reverse"` | `"forward"` | Направление. |
| `on` | string \| string[] | `["on"]` | Состояния, при которых вращается. |
| `valueMax` | number | — | Если скорость задаётся числом (атрибут `percentage`), значение = 100 %. |

Вращение останавливается плавно: скорость гасится, объект не «замирает» рывком.

### 6.5 Двери и окна — `door` / `{ action: "door" }`

Два режима: **поворот** (распашная) и **сдвиг** (раздвижная, штора).

| Поле | Тип | По умолч. | Описание |
|---|---|---|---|
| `slide` | boolean | `false` | `true` — сдвиг вместо поворота. |
| `hinge` | `"left"｜"right"｜"top"｜"bottom"` | — | Сторона, где петля (для поворота). Обязателен для аккуратной анимации. |
| `degrees` | number | `90` | Угол открывания. |
| `axis` | `"x"｜"y"｜"z"` | `"y"` | Ось поворота (обычно `y` — вертикальная). Для сдвига — направление движения. |
| `span` | number | `1` | Величина сдвига в метрах (для `slide`). |
| `open` | string \| string[] | `["on","open","opening"]` | Состояния «открыто». |
| `valueMax` | number | `100` | Для `cover` с `current_position`: значение = 100 %. |
| `rate` | number | `6` | Скорость анимации. |

Если задан `hinge`, поворот происходит вокруг края объекта, а не вокруг центра —
дверь выглядит как настоящая.

### 6.6 Текст состояния — `text` / `{ action: "text" }`

Подпись рисуется как спрайт поверх объекта и читается при любом масштабе.

| Поле | Тип | По умолч. | Описание |
|---|---|---|---|
| `template` | string | `"{state}"` | Шаблон подписи. Подстановки: `{state}`, `{value}`, `{name}`, `{unit}`, `{entity}`. |
| `prefix` | string | — | Текст перед значением. |
| `digits` | number | `1` | Знаков после запятой для `{value}`. |
| `scale` | number | `0.0035` | Размер подписи. |
| `elevation` | number | `0.15` | Высота над центром объекта. |
| `offset` | [x,y,z] | — | Точное смещение подписи. |
| `fontSize` | number | `30` | Размер шрифта на канве. |

```json
{ "entity": "sensor.outdoor_temp", "target": "Label_Temp",
  "text": { "template": "Улица: {value} {unit}", "digits": 1 } }
```

## 7. Условия

Условия используются в `colors`, `conditions`, `hide`/`showWhen`, `door.open`,
`light.on`, `rotate.on`.

| Запись | Значение |
|---|---|
| `"on"` | Состояние ровно `on` (регистр не важен). |
| `"!off"` | Любое состояние, кроме `off`. |
| `">50"`, `">=50"`, `"<10"`, `"<=10"`, `"==100"`, `"!=0"` | Числовое сравнение состояния. |
| `"/^heat/"` | Регулярное выражение по состоянию. |

Несколько условий для одного цвета задаются таблицей:

```json
"colors": { ">=30": "#ff0000", ">=20": "#ffaa00", "<20": "#00aaff" }
```

Проверяются по порядку, срабатывает первое совпавшее.

## 8. entityConfig — поля в редакторе карточки

По умолчанию для каждой привязки карточка создаёт поле выбора сущности
с доменом из `entity_id`. Уточнить можно здесь:

```json
{
  "entityConfig": {
    "sensor.power": {
      "name": "Мощность, Вт",
      "group": "Питание",
      "hint": "Влияет на цвет индикатора",
      "kind": "number",
      "overrides": { "required": true }
    }
  }
}
```

| Поле | Описание |
|---|---|
| `name` | Подпись поля. |
| `group` | Группа в форме. |
| `hint` | Пояснение под полем. |
| `domain` | Один домен для фильтра списка (`sensor`). |
| `kind` | Как читать значение: `raw`, `number`, `boolean`, `brightness`, `attribute`. |
| `overrides` | Любые поля привязки карточки: `required`, `unit`, `deviceClass`, `order`. |

## 9. params — настройки модели

Пользователь меняет их в редакторе карточки; доступны в коде через
`ctx.params`, если модель расширена кодом.

```json
"params": [
  { "key": "glow", "name": "Яркость свечения", "type": "range", "default": 0.6, "min": 0, "max": 1, "step": 0.05 }
]
```

Типы: `number`, `range`, `boolean`, `text`, `theme-color`, `color`, `select`.

## 10. Расширение кодом

Если данных мало (например, нужна своя анимация), пишется модуль модели.
Импорт ядра карточки нужен только для необязательных утилит вроде
`loadGeometry`. При установке через HACS на сервере лежит **один файл**
(`threejs-3d-card.js`), каталога `src/` там нет — поэтому импортировать ядро
имеет смысл только при ручной установке из архива (`dist/`), где путь такой:
`/local/<папка>/src/core/geometry.js`. Всё остальное (фабрика объектной модели,
three.js) доступно через глобальный API — см. §1.

```js
// Только для ручной установки из архива dist/:
const { loadGeometry } = await import("/local/threejs-3d-card/src/core/geometry.js");

export default {
  manifest: { id: "custom", name: "Своя модель", host: "external" },
  bindings: [],   // при необходимости — вручную
  async create(ctx) {
    const THREE = ctx.THREE;
    const model = await loadGeometry(ctx, { url: "/local/3d/thing.glb" });
    const group = new THREE.Group();
    group.add(model);
    return {
      root: group,
      external: true,
      applyState(key, info) { /* своя логика */ },
      frame(dt) { /* своя анимация */ },
      dispose() { /* освободить ресурсы */ },
    };
  },
};
```

Полный контракт модели — `docs/MODEL_API.md` в репозитории карточки.
